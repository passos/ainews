What Jev is: a structured evaluation model from TypeSafe. The input is a state and a set of noul (yes/no probability), choice, and score questions. The output is answers with probabilities. Context is 32k; input is $0.042 / 1M tokens and output is free Verified. It covers the "judgment" steps: pre-filter, five-dimension scoring, tags, grouping judgment, watch judgment, and source evaluation. It is billed through Workers AI, not from the credits you topped up in AI Gateway Inferred, so the ledger and the budget are kept separately by channel.

07 · How the work runs
  • One branch, one worktree, one PR per issue. After CI passes, auto-merge (squash). The first commit of the repo holds only documents and goes straight to main. Everything after that goes through PRs.
  • The timing of the detail work departs from my default rule: the rule says an issue carries an "implementation detail" section as soon as it is opened. But the repo has no code now. For M2–M4, the detail could only guess at files and interfaces, and it would be outdated once #2 lands. So M0 and M1 are detailed now and get the refined label. For M2–M4, scope, acceptance, and dependencies come first, and the detail is written before dispatch.
  • #2, #3, #6, #7, #11, and #14 involve idempotency, external semantics, or data integrity. They get one more cross-family review round before merge.
  • After an executing agent reports "all tests green", I check independently. I do not trust the report directly.
  • The review findings are already merged into the architecture contract: ledger leases, budget reservation, sequential grouping, revision key, review bound to version, publish only approved input, Funding and EDGAR modeled separately (see docs/plan/review-2026-10-22.md).
