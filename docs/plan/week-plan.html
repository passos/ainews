Jev 是什么：TypeSafe 的结构化评估模型。输入一段状态和一组 noul（是/否概率）、choice、score 问题，输出带概率的答案；上下文 32k；输入 $0.042 / 1M token，输出免费 已验证。它覆盖了预筛、五维评分、标签、归组判定、watch 判定和信源评估这些"判断"步骤。它走 Workers AI 计费，不在你给 AI Gateway 充的 credits 里 推断，所以账本和预算按渠道分开记。

07 · 执行方式
  • 每个 issue 一个分支、一个 worktree、一个 PR；CI 通过后 auto-merge（squash）。仓库的第一个 commit 只有文档，直接进 main，之后全部走 PR。
  • 细化的时机偏离了我的默认规则：规则要求 issue 一开出来就带"实现细化"。但仓库现在没有代码，M2–M4 的细化只能猜文件和接口，#2 落地后就会过期。所以 M0 和 M1 现在细化、打 refined 标签；M2–M4 先写范围、验收和依赖，派发前再细化。
  • #2、#3、#6、#7、#11、#14 牵涉幂等、外部语义或数据完整性，合并前再过一轮跨家族评审。
  • 执行 agent 报告"测试全绿"后，我独立复核，不直接相信报告。
  • 评审意见已经并入架构契约：账本租约、预算预留、顺序归组、revision 键、审核绑定版本、只发布已批准输入、Funding 和 EDGAR 单独建模（见 docs/plan/review-2026-10-22.md）。
