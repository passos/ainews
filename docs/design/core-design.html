Multi-industry news site: finds its own sources, writes its own daily digest

The backbone follows AIHOT (collect → model filtering and writing → group into events → daily digest → website and RSS), moved to Cloudflare: one Worker, D1, Queues, AI Gateway, Browser Run. One admin can add industries in the admin area. The sources of each industry can be added by hand, or AI can search, probe, and evaluate them and list them as candidates.

Relation to the Newsren plan: The plan aims at a "research agent for readers". ainews v1 does its Stage 1, plus a batch version of Stage 2: the Brief and the per-reader explanations are generated when an article is selected, so a reader never triggers a model call. Whether to go one step further depends on Q11 and Q12.

01 · Three basic differences from AIHOT
Industry = runtime data

The industry/ directory of AIHOT (categories, prompts, thresholds, sample sources) is deploy-time code: one deployment, one industry. ainews turns them into rows in D1, partitioned by industry_id, and they are created and edited in the admin area. The scoring prompt is data, not code.

Three processes + Postgres → one Worker

The three processes web / api / worker and the pg-boss queue become three entry points of one Worker: fetch (website, RSS, admin area), scheduled (timers), queue (collect, analyze, group). D1 has no locks and no interactive transactions, so serialization needs another way (see 06).

Sources can be found by AI

In AIHOT, people write sources into sources.json. ainews adds a discovery flow: draft search terms → Web Search API → probe for RSS or list pages → sample evaluation → into the candidate list; fetching starts only after the admin approves.

04 · Inherited invariants

Rules in AIHOT that hold for every site are kept as they are

Opening a page does not trigger a model call
Models are called only in the queue and scheduled entry points. The code path of the fetch entry point does not import model modules. An architecture test that scans imports guards this. If Q11 picks Ask, a question only goes into the queue and the queue entry point answers it.
Fetch only approved addresses
The body fetch ladder (see 07) fetches only approved sources, plus the domains in the primary-source allowlist of each section. URLs submitted by readers are not fetched, and there is no unlimited browsing.
All public outputs read from one read layer
src/publication/ is the only read entry for website pages, RSS (and an API later). It reads only the published_items projection table, events, and reports.
Paid calls are idempotent and have a budget breaker
The llm_calls table is unique on logical_key (task + input version + model + prompt version). A call in the unknown state is not resent automatically. The AI Gateway spend limit is the hard cap. The daily budget check inside the app is the soft cap.
A safety valve opens only when set to true
COLLECT_ENABLED, MODEL_CALLS_ENABLED, DISCOVERY_ENABLED, BROWSER_RUN_ENABLED, THIRD_PARTY_READER_ENABLED are off by default. Tests connect only to local fake servers and never use the external network.
Sources show only the summary and the original link
The body may be fetched for analysis. See Q14 for how it is stored. The page shows only the summary and the original link. sources.fulltext is 0 by default. Show the full text only when the source clearly allows it.
Public content is anonymous; the admin area allows only the admin
The admin and a visitor see the same public pages. See question Q2 for the admin entry.
05 · System components

One Worker, three entry points

  • Why not split into several Workers: One admin and a small scale (see Q8) mean one Worker is simple to deploy and roll back. The boundaries between the three entry points are guarded by directories and the architecture test, not by processes.
  • Workflows are not used for now: All steps of one article fit in one queue message, and llm_calls guarantees idempotency. If source discovery runs past a single 15 minutes, switch it to a Workflow.
  • Front-end framework (Hono JSX SSR or React Router) is an architecture choice. Run a cross-family review after the scope is confirmed.
06 · Two main flows

Content pipeline and source discovery

What guarantees idempotency and serialization on D1

AIHOT relies on Postgres FOR UPDATE, advisory locks, and "enqueue inside the transaction". D1 has none of these. It has only batch() (atomicity still to be verified). The ainews equivalents:

What must holdAIHOTainews
The same article is not stored twiceidentity_key UNIQUEarticles.url_hash UNIQUE + INSERT … ON CONFLICT DO NOTHING
The same model call is not paid twicereceipts + FOR UPDATEllm_calls.logical_key UNIQUE: insert pending first, and only the winner makes the call. A completed hit uses the result directly
The same new event is not created twicegroup queue concurrency 1The group queue uses max_concurrency: 1, the same approach
A database write and an enqueue are not lostenqueue(tx) in the same transactionD1 and Queues share no transaction: write the state first, then send the message. Cron resends items stuck in the middle state every 5 minutes
The budget is not exceededadvisory lock serializes the checkAI Gateway spend limit (eventually consistent, so short bursts may slightly exceed it) + check the spend of the day before enqueue
07 · Body fetch ladder

Try each tier from cheap to expensive; each source remembers the tier that works

RSS often gives only a title and a sentence or two, but the Brief, the evidence labels, and the later Ask all need the body. When a new source is approved, probe once and write the cheapest usable tier into sources.fetch_rung. Probe again after 3 failures in a row. Each article records the tier actually used, as provenance information.

  • How many pages Browser Run can carry: 10 hours = 36,000 seconds. At 5 seconds per page, about 7,000 pages per month cost nothing extra. Assumed: 5 seconds per page is an estimate. After launch, replace it with the measured value of X-Browser-Ms-Used.
  • robots.txt: For Browser Run, only /crawl states that it obeys robots.txt. The /markdown documentation says nothing. Jina must be enabled explicitly. So for tiers 1–4 we read robots.txt ourselves first. If it forbids, we stop and mark the source "RSS only". Assumed: /markdown itself does not check robots.txt.
  • Why tier 3 comes before tier 4: Within the free quota it costs nothing. The price is one more external dependency, and the URL goes to a third party. If you care more about using only Cloudflare, pick "do not use" in Q13, and the ladder becomes 0 → 1 → 2 → 4.
  • Paid step: Like a model call, tier 4 records its time in the same ledger llm_calls (type browser), and the daily budget limits both together.
